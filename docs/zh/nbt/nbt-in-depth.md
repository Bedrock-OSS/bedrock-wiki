NBT（Named Binary Tag，命名二进制标签）是一种二进制层面的数据编码格式名称，你肯定知道 JSON 格式，它是文本层面的。因此，我们可以使用 JSON 格式来举例说明，你可能也注意到 Minecraft 本身在 Java 版命令或简化的基岩版命令（`/give`、`/replaceitem`）中使用 JSON 来表示 NBT。
参见 [NBT 命令](/commands/giving-nbt-items)。

在本文中，我们将比你所预期的更详细地介绍 NBT。你在命令部分看到的内容与实际的 NBT 相去甚远，我们将向你展示 NBT 是如何工作的、如何读取它们，以及 `Minecraft Bedrock Edition` 本身是如何使用它们的。

## NBT 标签和数据类型

NBT 和 JSON 一样有给定的类型，并且知道如何读取它们。例如，JSON 知道 compound 对象以符号 `{` 开始，以 `}` 结束，它还知道当需要读取 String 时，String 总是以符号 `"` 开始，以 `"` 结束。这意味着我们需要学习读取和理解 NBT，因此你需要知道复合对象何时开始，以及如何读取各个类型。
现在让我们看一下 NBT 类型对应的 NBT 标签表以及它们在 NBT 中的标记方式。如前所述，NBT 在二进制层面工作，因此你需要知道最小的数据类型是 byte，它占用 8 位。
各个类型可以包含多个字节，但它们永远不能多或少 1/2 字节，这是不可能的！
我们也不能规定标签应该如何命名，因为每个人对 NBT 标签的称呼可能不同，但它们必须具有相同的二进制基础（`id`），id 由一个字节表示。

|      名称        | 二进制 ID |    二进制大小    | 描述                                                                                                                                                     |
| :-------------: | --------: | :---------------: | :-------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|      Byte       |      0x01 |  1 byte (8-bits)  | 单字节整数                                                                                                                                                |
|  Int16 (short)  |      0x02 | 2 bytes (16-bits) | 双字节整数                                                                                                                                              |
| Int32 (integer) |      0x03 | 4 bytes (32-bits) | 四字节整数                                                                                                                                             |
|  Int64 (long)   |      0x04 | 8 bytes (64-bits) | 八字节整数                                                                                                                                           |
|      Float      |      0x05 | 4 bytes (32-bits) | 四字节（单精度）浮点数，采用常规小数精度，按照 IEEE 754                                                            |
|     double      |      0x06 | 8 bytes (64-bits) | 八字节（双精度）浮点数，采用更高的小数精度，按照 IEEE 754                                                           |
|     String      |      0x08 |    预定义     | 具有预定义大小的字符串类型。文本使用 UTF-8 编码                                                                                              |
|      List       |      0x09 |    预定义     | 具有预定义大小和元素类型的列表类型                                                                               |
|    Compound     | 0x0A (10) |     未定义     | Compound 类型，Compound 没有预定义大小，因此必须读取键值对直到遇到结束 compound 的标签。 |
| End of Compound |      0x00 |      1 byte       | 此标签不是一种类型，而只是一个标签，并且只能根据 compound 来使用。它标记 compound 的结束                                            |
|    Byte List    |      0x07 |    预定义     | Byte 列表类型和预定义大小，Minecraft 基岩版不常用                                                                           |
|    Int List     | 0x0B (11) |    预定义     | Int 列表类型和预定义大小，Minecraft 基岩版不常用                                                                            |
|    Long List    | 0x0C (12) |    预定义     | Long 列表类型和预定义大小，Minecraft 基岩版不常用                                                                           |

你可能注意到没有像 JSON 中那样的布尔值，这意味着我们将使用 Byte 用 1 和 0 来表示 true/false 值。

## 如何读取/写入 NBT 标签

所有数字的读取方法相同，读取该数字标签类型大小的字节数。例如：Int16（short）大小为 2 字节，因此我会读取 2 字节，但你需要知道 Minecraft 基岩版使用[小端序](#little-endian)，与 Java 版使用大端序不同。
[小端序](#little-endian) 是一种写入或读取数字字节的方式。

### 读取类型

类型始终是 1 字节大小，因此我们读取类型，然后找出接下来要读取什么标签。

### 读取数字

读取数字时，必须知道我们要读取的是哪种类型的数字，我们可以通过读取类型（_[读取类型](#reading-types))_）来得知。
然后，当我们知道要读取哪种类型的数字时，就读取它。例如，如果我们知道类型是 `3`，就在表中查找，知道类型 3 是 4 字节大小的数字，因此读取 4 字节。
所有数字 **_基岩版_** 都使用[小端序](#little-endian)方法读取/写入。

### 读取字符串

读取字符串时，需要知道它的字节长度，这个字符串长度总是用 Int16（short）`2 字节`（[如何读取数字](#reading-numbers)）写在字符串之前，
即首先读取数字，然后读取之前读取的数字的字节数，知道字节数后，我们可以通过 UTF-8 编码从中获取文本。

### 读取列表

读取列表时，我们必须首先读取该列表的类型（[类型](#reading-types)），无论此列表包含数字、其他列表还是字符串等。
因此首先读取此列表的类型，然后读取元素数量，它被写成 Int32（int）数字，因此读取 4 字节，现在我们知道了元素的类型和数量，因此根据之前读取的数字多次读取该类型。
读取列表的大小与读取字符串的大小不同！应该读取 Int32 而不是 Int16！此方法不适用于 `Byte-List、Int-List、Long-List`！

### 读取 Compound

Compound 有所有带名称的属性，因此读取属性时，总是需要读取它的名称。读取 Compound 的过程相当简单。
首先，读取类型，类型可以是任何值，但如果它等于一个空字节，那就是 compound 的结束，然后我们停止读取，但如果类型不等于 Compound 结束标签，
那么它是我们将要读取的属性的有效类型。读取的属性后面总是跟着需要作为[字符串](#reading-strings)读取的名称（键），读取字符串后，我们就可以读取值了。

## Minecraft 基岩版 NBT 文件

读取 Minecraft NBT 文件时，始终要注意文件开头是否有 Bedrock 头，参见 [Bedrock NBT 头](#bedrock-nbt-file-header)，但并非所有基岩版 NBT 文件都包含此头，
例如 `.mcstructure` 也不包含 Bedrock NBT 头，而 `level.dat` 则包含。你还需要注意文件中的根元素，即 List 或 compound，根元素也看起来像一个属性，因此你需要读取这个根属性的名称，虽然基岩版不使用这些名称，因此这些名称是空的，但它们就在那里。
下面是 `.mcstructure` 的样子，其中 JSON 表示 NBT。

```json
"": {
    "format_version":1,
    "size":[], //...
    "structure":{}, //...
    "structure_world_origin":[] //..
}
```

:::warning
此示例表明，读取基本元素的名称也是必要的，尽管它通常未使用且为空。
:::

## 写入 NBT

写入没有特定的过程，因为方法与读取相同，但方向相反。
这就是为什么我们建议首先理解 NBT 并学会正确地读取它，然后写入 NBT 就不会困难了。

## Bedrock NBT 文件头

NBT 基岩版头由两个 4 字节的数字表示，第一个始终是 8（除非在 `level.dat` 中，它表示存储版本）第二个表示 NBT 结构的大小（以字节为单位）。
例如 - `08 00 00 00` - `bf 00 00 00` - <始终 8> <始终为 NBT 结构的大小 - 排除头部的 8 字节>

## 小端序

小端序是向流或文件写入数字字节的常用方法。
这不是什么科学，很容易理解。因此，如果 Int16（short）的值是 `0x5a72`，则将其转换为字节 [`0x5a`, `0x72`]，然后反转它们的顺序，即 [`0x72`, `0x5a`]，写入文件：`72 5a`。
这看起来可能不合逻辑，但小端序在写入和读取文件时几乎总是使用。单字节在两种方法中相同，因为它只有一个字节。
例如：

-   Int64（long）`0x11223344aabbccdd`
-   拆分为 8 字节 `0x11 0x22 0x33 0x44 0xAA 0xBB 0xCC 0xDD`
-   反转 `0xDD 0xCC 0xBB 0xAA 0x44 0x33 0x22 0x11`
-   写入 `dd cc bb aa   44 33 22 11`
-   完成（读取数字时只需按此示例的反向进行）

## 网络小端序

网络小端序不太常见，仅用于基岩版协议中序列化 NBT。它使用可变长度整数（也称为 VarInt）。

VarInt 将整数编码为 7 位块；每个字节的 MSB 都被设置，除了最后一个字节会被清除。
有符号值首先使用 ZigZag 编码转换为无符号表示（也可在下面链接的页面中找到描述），然后与其他无符号数字一样进行编码。
有关 VarInt 的更多信息，请参阅 [Google 的 protobuf 文档](https://protobuf.dev/programming-guides/encoding/)。

NBT 中的以下所有数据类型都用 VarInt 表示：`Int32` 和 `Int64`。
（这不包括 `Byte` 和 `Int16`，以及使用小端序编码的 `Float` 和 `Double`，因此称为网络小端序）。

更多变化：

-   字符串前面有一个使用 VarInt 编码的 Int32 来存储其长度。
-   列表前面也有一个使用 VarInt 编码的 Int32 来存储其长度。
