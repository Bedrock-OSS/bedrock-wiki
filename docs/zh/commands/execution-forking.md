## 简介

[来自基岩版命令社区 (BCC) Discord](https://bedrockcommands.org/)

**执行分叉**（也称为*实例化*或*嵌套*）是一种在同一个 tick 内触发单条命令多次的技术。这是通过利用针对多个实体的选择器来实现的，有效地"分叉"每个找到的目标的执行路径。

### 问题：速度与效率
想象你正在创建一个子弹系统。为确保子弹不会穿过墙壁，你需要每 1 方块检查一次碰撞。如果每 tick 移动子弹 1 方块，它会看起来很慢且卡顿。

为让它瞬间移动 32 方块同时仍检查碰撞，你需要在单个 tick 内运行 32 次移动和检查逻辑。手动放置 32 个命令块效率低下且难以维护。**执行分叉**通过使用单条命令生成这 32 个实例来解决这个问题。

## 理解实例化

在基岩版中，只有一个命令块并不意味着它只运行一条命令。当你使用一个选择器（如 `@a` 或 `@e`）识别多个目标时，你为每个被选择的实体创建了该命令的一个新**实例**。

考虑这个命令：

```yaml
execute at @a run particle minecraft:basic_flame_particle ~ ~ ~
```

如果有 5 个玩家在线，`at @a` 子命令会分叉执行。不是一条粒子命令，而是运行 **5 个独立实例**（每个玩家位置一个）。

## 乘法执行分叉（MEF）

通过"嵌套"这些执行分叉，你可以指数级增加命令运行的次数。这通常被称为**执行乘数**或**嵌套**。

当你堆叠多个 `as` 或 `at` 子命令时，每个新的分叉都会乘以现有的分叉。

### 嵌套的数学

创建的实例总数遵循一个简单的幂公式：

` 实例数 = n^x `

其中 `n` 是每个子命令针对的实体数量，`x` 是你嵌套执行的次数。

### 示例：堆叠分支

```yaml
execute as @e[c=2] as @e[c=2] as @e[c=2] run say hi
```

在这个例子中，命令将在一个 tick 中说 `hi` **8 次**：

1.  **第一次分叉：** 初始实例针对 2 个实体 → **2 个实例**。
2.  **第二次分叉：** 这 2 个实例各自针对另外 2 个实体 → **4 个实例**。
3.  **第三次分叉：** 这 4 个实例各自针对另外 2 个实体 → **8 个实例**。

### 常见用例

* **光线投射：** 强制"子弹"或"激光"在一个 tick 中向前移动多步以防止穿墙。
* **批量实体更新：** 在已加载区域对每个实体应用复杂逻辑，而无需使用多个重复命令块。
* **高速计时器：** 每 tick 运行记分板计时器多次以获得亚 tick 精度。

:::tip
分叉时始终使用 `c=`（计数）或 `type=` 限制。如果你意外分叉 `@e`（所有实体）而没有限制，你可以瞬间创建数百个实例，导致严重的服务器卡顿或"命令溢出"。
:::
