## 关于定位地图的计划？

-   **问**：我看到自定义拼图游戏的定位地图已经可以实现，但是否有更多"官方"支持的计划（例如自定义图标/地图名称）？
-   **答**：这在我们的关注范围内，但不是短期路线图上的项目。

## 有计划将原版结构更新为当前的拼图系统吗？

-   **问**：如果有一天我们可以修改所有原版结构，比如村庄、掠夺者前哨站等，那就太棒了。据我了解，它们使用的是旧版拼图系统，或者完全不同的系统。但如果这些能像试炼室和遗迹那样转移到我们当前的拼图系统就好了。我觉得这是社区最想要的——能够修改每一个原版结构。
-   **答**：我们希望将更多原版结构转换为使用新系统，但这不在短期或中期路线图上。当前可用的原版结构是试炼室和遗迹。你们希望先看到哪个？
-   **答**：也值得注意的是，本次问答中的人员不能代表原版团队及其意图发言。

## 其他维度的自定义生物群系

-   **问**：当自定义生物群系回归 Bedrock 时，下界和末地会获得更多支持吗？据我所知，自定义末地生物群系以前从未存在过……
-   **答**：资源包中的 client_biome 设置（用于视觉效果和音频）现在应该在任何生物群系中都能工作，包括下界和末地。对于影响行为和世界生成的方面，我们同意如果能影响这些维度也很棒，但路线图上还没有相关内容。

## 是否会为自定义生物群系添加自定义环境粒子的选项？

-   **问**：当自定义生物群系还可以创建时，无需外部方法就能添加到其中的粒子只有来自下界的粒子。但如果未来我们可以添加任何自定义粒子来设置生物群系，那就太好了。
-   **答**：自定义环境粒子是我们过去研究过的东西，也是我们可以考虑的事情。任何您能提供的关于如何使用它们的信息，我们都乐意接受。

## 自定义维度

-   **问**：为未来风格附加包引入新维度的能力，可以编辑整个维度，从高度限制到维度生成系统，就像 Java 版一样。在 Java 版中我们可以非常轻松地创建自定义维度，在 Bedrock 上也能这样就太好了。
-   **答**：我们 definitely 看到自定义维度对创作者很重要，但与此同时我们正专注于世界生成的许多元素。

    在近期，我们将建立在功能和拼图结构的基础上，以及更多能力，以便向更多生物群系自定义化方向发展。

## `/place feature` 命令

-   **问**：未来是否会有用命令放置功能的选项？
-   **答**：这在我们的短期路线图上！

## 能否增加拼图块宽度？

-   **问**：128 太小了，就我个人而言，我的 Marketplace 项目需要一个 6 倍于此的数字。如果不行，能否让每个拼图结构自定义此数值？
-   **答**：128 不是严格限制。然而，当我们生成一个区块时，我们会检查到 8 个区块远的地方，以允许更大的结构生成并构建到该区块中。但由于性能考虑，超过 128 的任何内容可能会有点令人担忧。另一点是，这是从中心计算的，不是总宽度！意味着 128 是半宽而不是全宽，即 256。😄

## Molang 会有性能提升吗？

-   **问**：使用 Molang 的 3D 噪声进行自定义地形生成很容易导致世界加载需要 5 分钟或更长时间，即使你只使用 1 个方块类型和 1 个功能及功能规则，这实际上长得离谱。
-   **答**：我们正在研究 q.noise 的性能，看看能否做更多类似缓存的事情让它更高效地工作。同时我可能会避免大量使用它。

## 为什么拼图花了这么长时间？

-   **问**：我们使用拼图块已经很长时间了……为什么它从来没有完全可用？为什么让它可用需要这么长时间？

    我只是好奇为什么我们被搁置了半生不熟的解决方案这么久，是不是有什么原因让你们当时放弃了添加拼图？

    是什么促使你们最终决定让创作者可以使用它们？

-   **答**：说实话，过去我们有时会做一个平台功能但没有以令人满意或及时的方式完成——例如节日创作者功能。在大多数情况下，这意味着我们需要更好地将东西融入稳定平台，尽管在某些情况下如果实验看起来不会有结果可能需要更快地削减实验。我们正在努力做得更好，如果我们开始做某事，就把它融入平台，当然我们不可能做到完美。

    关于为什么是现在，我们有一个能力 backlog，我们努力工作以将这些能力添加到平台供人们使用，而现在我们正在研究一些基础的世界生成元素。在推出这些能力之前，很多時候我们需要做很多更新来稳定该区域，使其更容易升级、性能更好，并且能够容忍你们将要构建的所有内容（即使如此，这些东西也会有很多方式出问题）。。

## 自定义结构中的生成点

-   **问**：之前结构框架的一个缺陷是我们无法放置实体或创建生成点（这是下界堡垒、海洋纪念碑和其他结构反复生成实体的方式）。我通常会创建一个高频tick方块来生成一个实体并删除自己，但这可能导致一些问题。

    随着结构得到一些关注，拼图变得可用，我们现在可以在结构中放置实体，但是否有计划在世界生成框架中添加生成点支持？

-   **答**：大家好！很喜欢这里的讨论。这正在开发中！虽然考虑到刷怪系统有点脆弱（**咳嗽**农场），我们想确保我们尽一切可能来平滑边缘。所以……那意味着更多测试。期待更多内容很快出现在实验中！
-   **问**：这是否意味着生成率也能与 Java 版持平？
-   **答**：这是我们的目标！一旦我们把它放入实验（很快），我们肯定需要你们的所有帮助来确保世界仍然看起来平衡，刷怪没有偏移。这包括任何影响/改进刷怪农场

## 结构碰撞

-   **问**：人们一直在使用的变通方法，比如生成实体，或使用命令块在结构中生成（例如创建地牢时的一行），总是有机会碰撞，尤其是地下结构。

    例如，试炼室可能与其他结构交叉，摧毁它们。我希望在拼图块以及一般结构中能看到一个功能，可以防止这种碰撞发生。

    我想知道 Mojang 团队对此的想法

-   **答**：大家好！这肯定在我们的关注范围内，尽管目前没有具体的工作计划。特别是因为这里有一个更深层的问题。

## 目录结构问题

-   **问**：使用新的拼图系统，所有相关文件都放在 `worldgen` 下。是否有计划将 `structures`、`features`、`feature_rules` 和 `biomes` 移入此文件夹？拼图集放在 `worldgraph` 下有什么原因，还是只是为了对等？
-   **答**：我们把拼图相关的东西归为一组，因为这些文件在逻辑上是为拼图相关的东西分组的。"worldgen" 作为分组文件夹的名字……如果 features 和 feature rules 在外面，这是一个有趣的选择；我们可能会在将来调整其他文件或文件夹，但目前没有将 features 和 feature rules 移入其中的计划。

## 脚本

-   **问**：是否有计划在世界生成中启用脚本集成？例如，可以根据世界事件修改结构放置或内容的脚本。
-   **答**：我们正在探索一些将脚本与世界生成集成的方法，但正如你们注意到的，这有点困难，因为让脚本"接管"区块生成的重要部分不会有很好的性能。🙂

    但也许有些地方我们可以调用脚本来"决定"某事。我不知道脚本在世界生成的短期路线图上的位置。

    我几年前的第一个演示之一是在脚本中构建地牢生成器，但很难让它工作，因为大多数逻辑是关于如何跨tick对所有方块放置进行时间分片（还要处理区块加载语义）来构建这个东西。

    从那以后，脚本中有了更多支持，例如利用tick中空闲周期的生成器功能——而且也许如果你将其使用限制在高性能设备（强大的专用服务器）或真正优化——它可能非常可行且很棒。我知道社区中一些人沿着这些方向构建了一些很酷的东西。

-   **答**：我在其他地方聊过，但一个有趣的原型是使用 webworker 模型来旋转 JavaScript 实际上可以在其他线程上运行诸如世界生成之类的东西。

    一个不错的想法是提供一个不同的 API 表面（你可以导入的不同模块），其中包含特定的世界生成相关 API。

    目前这只是有趣的想法，但也许有一天！

## 为什么不允许使用 conditional_list 和 sculk_patch_feature 功能？

-   **问**：我知道 conditional_list 被删除了，但为什么还没有恢复？为什么他们从不允许使用 sculk_patch_feature？
-   **答**：conditional_list 需要更多工作来使其健壮——我们正在研究它可能归属的位置。sculk_patch_feature 結果证明过于偏向原版；我们可能会在某个时候寻找更通用的替代方案。
-   **问**：这是否意味着你们将来反对非常偏向原版的功能类型？毕竟树功能就是这样的。
-   **答**：一般来说，我会说平台功能、原版-ish 和太偏向原版而不能成为健壮的平台项目之间的界限有点模糊。我想这就是边界所在的地方 🙂

## 缺少的拼图功能会从 Java 版添加吗？

-   **问**：Java 版的拼图结构有几个似乎不存在的功能：
    -   从结构放置功能（即 `minecraft:feature_pool_element`）
    -   模板池别名（Java 版用它来选择试炼室拥有哪组试炼生成器，这在 Bedrock 中如何工作？）
-   **答**：大家好！正如你们所注意到的，我们在新拼图系统中有生成覆盖，但目前不是由数据驱动的拼图结构的数据驱动。团队目前正在简化生成规则，然后才能完全暴露该生成系统。
-   **问**：

    > 团队正在简化生成规则

    整个系统？也就是说，实体 BP JSON 文件中 elusive 的 `spawn_category` 和整个 `spawn_rules` 文件夹？这意味着先简化然后扩展功能？

-   **答**：是的——与所有重构一样，必须从基础系统开始。我们即将让刷怪系统与 Java 持平。同时，我们正在简化生成规则，以便当我们确实暴露这些功能时，它们更易于使用！

    Bedrock 世界生成的思考方式与 Java 上的做法有何关系和不同？

## 世界生成路线图

-   **问**：一段时间以来，玩家可以知道 Mojang 正在做什么，库中有什么，或者它在考虑什么
    但非市场附属的创作者不知道会发生什么，直到有人要求时间表或它发布我希望我们得到 1 年时间表，这样我们可以开始学习或准备它

    我不介意事情延迟；我只是想了解你们正在考虑或积极做什么

-   **答**：世界生成的路线图会有点长。我们现在开始了一些元素——改进方块功能和功能（参见之前的问答：），然后继续研究嵌入世界的方法（功能、拼图结构）。然后，我们确实希望从生物群系能力开始。

    原版现在的生物群系工作方式很复杂，找到可行的解决方案一直具有挑战性，但我们正在积极工作。我们不知道时间表可能是什么，但我们希望在未来一年分享更多潜在设计。

    就生物群系可能包含的内容而言，我们知道许多技术需求：噪声图、比例、天气、雾、声。我们的目标是创建一个考虑您需求的健壮解决方案。我们很乐意知道您对生物群系的前 5-10 个必须有或应该有的需求！

## 有计划修复结构模板功能大小限制吗？

-   **问**：实际上限制是 48x48 因为区块，有计划修复或增加大小限制吗？
-   **答**：对不起回复晚了，但基于区块大小限制和世界生成的工作方式，提高这个限制有点棘手。我认为对于较大的结构，建议人们考虑拼图结构系统。

## 为什么不提供生成结构切换？

-   **问**：我对未来更多可能的世界生成功能感到非常好奇，我想知道 Bedrock 上缺乏生成结构切换是否与自定义世界生成是 WIP 有关，还是只是优先级较低。当使用附加包自定义我的游戏时，我经常发现自己希望能够更改或删除原版结构。如果这不能回答，我很抱歉，我不知道附加包和世界设置的开发有多交织。

-   **答**：很喜欢这里的讨论。要真正释放定制世界生成各个方面的力量，我们需要自定义生物群系。这有望让我们能够添加我们通常无法以hack方式触及的世界生成部分的 API。

## 子区块？
