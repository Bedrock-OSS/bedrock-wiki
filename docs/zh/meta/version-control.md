版本控制是一种迭代备份代码的概念，这样您就可以根据需要回滚到特定版本。版本控制最基本可以通过每天（或每个版本）获取附加包的 `.zip` 并将其上传到 Google Drive（或本地保存）来实现。这并非不合理，但它有三个显著的困难，而正确的 VCS（版本控制系统）可以解决：

-   不容易比较版本
-   不容易真正回滚到以前的版本
-   对于团队协作没有任何帮助

本教程将教您一个名为 `git` 的工具和名为 `GitHub` 的免费在线 git 存储服务的基础知识。任何人都可以跟随，但如果您在团队环境中工作或经常因为忘记备份而丢失工作，您将获得最大收益。

本教程不会直接关注教授 `git` 或 GitHub，因为外部知识来源更好地完成这一点。焦点将是在掌握基础知识后为 Minecraft 设置这些工具。

## Git

`git` 是安装在本地机器上的工具，允许您对文件进行版本控制。您可以`commit` 更改到您的文件，并带有简短消息（例如"修复了龙在被驯服后无法飞行的 bug"），查看完整的更改列表，并快速跳回特定更改。

Git 非常强大，是所有主要编程项目的默认工具。MC 工作最大的缺点是它很复杂。学习时要有耐心。

有关 `git` 的完整演练，您应该遵循以下 [git 教程](https://www.atlassian.com/git/tutorials/what-is-git)。

## GitHub

GitHub 是您在线托管的 git 项目（`repository`）。这允许多人同时处理同一个项目并协作。这对地图制作非常有帮助。通过在 Github 上托管，您还可以（可选）使您的代码公开，使与世界共享附加包变得前所未有的容易。

有关使用 `Github` 的完整演练，您应该遵循此 [github 教程](https://guides.github.com/activities/hello-world/)。

## 设置 Git

这假设您正在将一个现有项目添加到 git。如果从零开始，步骤类似。

### 结构

使用 `git` 进行附加包的最大问题是 `git` 通常通过封装一个文件夹并管理它来工作。当然，在 Bedrock 附加包中，资源分布在两个文件夹中：BP 和 RP。为了解决这个问题，我们将把我们的仓库完全放在 `com.mojang` 文件夹之外，然后使用 Windows  junctions 将文件夹"复制"进去。

将项目放在单独的位置有很多优势：

-   我们可以根据需要包含其他文件，如配置文件、工具、笔记、.bb 文件等
-   我们可以将 RP 和 BP 合并到一个仓库
-   我们所有的项目都可以在一个简单的位置轻松查看，而不是嵌套在 com.mojang 深处

### 创建 Git 仓库

为您的项目选择一个方便的位置。我把 mine 放在 `C:/sirlich/projects`。创建一个新文件夹，地图名称。我们将使用 `wiki` 作为我们模拟项目的名称。

右键单击文件夹，然后单击"Open git Bash"。如果此选项不出现，您可以从开始菜单打开 `git bash` 并导航到您的项目文件夹。如果您没有安装 `git bash`，您应该现在安装。

输入：`git init`。这将在您的项目中创建一个空白仓库。

### 链接您现有的 RP 和 BP

下一步是让仓库知道您的 RP 和 BP 文件夹。我们将使用 Windows 符号链接"junctions"。当我们创建 junction 时，我们实质上在文件系统中创建了一个虫洞，使您的文件看起来像同时在两个地方。删除/编辑/添加文件会被完美复制。

输入：`mklink /J wiki_RP "C:/path/to/RP/in/com/mojang"`
输入：`mklink /J wiki_BP "C:/path/to/BP/in/com/mojang"`

完成后，您应该在项目文件夹中看到 `wiki_RP` 和 `wiki_BP`，其中包含您的所有资源、现有文件等。

您现在可以按照上面的教程将此仓库推送到 `github`。

### 额外文件

因为我们基于符号链接创建了仓库，我们可以将任何我们想要的东西添加到项目文件夹中，而不必担心破坏 com.mojang 文件夹。我喜欢跟踪 `.bb` 文件、封面艺术文件（`.kra` 等）。

您也可以添加笔记、视频文件或任何您想跟踪的内容。

### 使用您的 VCS 工作

使用 VCS 时要记住的主要事项：

-   始终在开始工作前 `pull`
-   经常 commit 和 `push`
-   始终在停止工作前 `push`
-   如果您的文件搞砸了，您可以随时重置到最后工作的版本。如果您经常 commit/push，希望这不会太久。
-   始终，而且我意思是始终写出好的 commit 消息。当您必须回滚时，这至关重要。
