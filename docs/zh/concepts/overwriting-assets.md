## 附加组件层级

附加组件系统是逐层构建的，每个包都添加在它之前的包之上。即使你只添加了一个包，也有一个隐含的_默认_包始终被添加。当你添加自定义内容时，此内容将可以完全访问所有默认文件。

### 访问默认文件

这种分层结构非常有用，因为它允许我们访问默认文件中的内容，而无需将它们复制/粘贴到你的附加组件中。例如，你可以访问 `blocks/stone.png` 而无需将其移动到你的附加组件中！只需将其设置为你的自定义实体的纹理，它就可以直接使用。这对于模型、渲染控制器或音效等东西特别有用。

如果默认资源发生变化，例如 [JAPPA](https://twitter.com/JasperBoerstra?ref_src=twsrc%5Egoogle%7Ctwcamp%5Eserp%7Ctwgr%5Eauthor) 更新了石头纹理，你的附加组件也会收到更新，因为你依赖的是实际的动态默认资源。

你应该尽量经常使用这种层级系统。如果你不_需要_将某些东西复制/粘贴到你的附加组件中，就不要这样做。

:::warning
绝对不能在默认资源/行为包的副本中制作附加组件。这会使你的附加组件下载文件变得非常大，并且会降低性能。始终从一个空白的附加组件开始，然后复制/粘贴你想要覆盖的文件。
:::

## 覆盖资源

包层级还允许我们通过_覆盖_具有相同路径或相同标识符的文件来覆盖默认资源。我们的新文件将替换默认文件中使用的文件，从而允许我们更改纹理、音效、实体行为等。

:::warning
不同的资源有不同的覆盖方法，请小心为每种类型使用正确的方法！
:::

### 按路径覆盖

通过_路径_引用且_没有标识符_的资源可以通过将新资源放入相同路径来覆盖。以下内容可以通过这种方式覆盖：

-   函数
-   战利品表
-   纹理
-   音效
-   交易表

当你覆盖这些文件时，覆盖是绝对的：新资源将完全替换旧资源。

:::tip
**示例**：如果你想替换红石矿石纹理，只需将新文件放在 `textures/blocks/redstone_ore.png`。
:::

### 按标识符覆盖

许多资源不是由名称而是由标识符定义的！要覆盖这些资源，只需创建一个具有相同标识符的新文件，无论文件路径如何。以下内容可以通过这种方式覆盖：

-   BP 实体
-   RP 实体
-   动画
-   模型
-   动画控制器
-   生成规则
-   配方
-   粒子
-   渲染控制器

当你覆盖这些文件时，覆盖是绝对的：新资源将完全替换旧资源。

:::tip
**示例**：如果你想让恶魂有更高的生命值，只需创建一个具有 `minecraft:ghast` 标识符的新 BP 实体，以及使恶魂发挥作用所需的所有行为。

请记住，实体文件不会合并在一起，因此你需要先复制整个 BP 恶魂文件，然后_然后_编辑生命值。仅仅创建一个包含高生命值组件的 `minecraft:ghast` 是行不通的。
:::

### 通过引用文件覆盖

许多资源也可以注册到某种“注册系统”文件中。这些文件很有趣，因为与其他资源类型不同，它们是_合并在一起_而不是_覆盖_的。这意味着在定义这些文件时，你不需要从默认资源中复制。你可以从一个空文件开始，然后覆盖你想要的特定定义。

以下文件以这种方式工作：

-   所有 UI 文件
-   [所有语言文件](/text/text-intro)
-   `item_texture.json`
-   `flipbook_textures.json`
-   `terrain_texture.json`
-   `sounds.json`
-   `music_definitions.json`
-   `sound_definitions.json`

:::tip
**示例：** 假设你想使用引用文件覆盖 `sugar` 纹理。你可以通过创建一个包含以下内容的 `item_texture.json` 来实现：

<CodeHeader></CodeHeader>

```json
{
    "texture_data": {
        "sugar": {
            "textures": "textures/path/to/my/sugar"
        }
    }
}
```

这个_定义_将与默认的 `item_texture.json` 合并，并将覆盖短名称 `sugar`。当默认物品访问此短名称时，它将获得对你的自定义纹理路径的引用，而不是糖的实际纹理路径。
:::

## 覆盖的风险

由于附加组件主要_覆盖_彼此而不是_合并_，让两个不兼容的附加组件协同工作可能会非常困难。例如，如果你尝试合并两个覆盖恶魂行为的附加组件（例如，一个让它们非常快，一个让它们非常大），你应用_第二个_的附加组件将覆盖第一个。

这主要是 `player.json`（在 RP 或 BP 中）的问题，因为这个文件经常用于游戏目的。

## 无法覆盖的内容

并非所有东西都可以覆盖，以下是任何描述的方法都无法覆盖的内容列表：

-   默认物品（并非全部）
-   默认方块
-   默认雾效（创建具有其他命名空间的雾效并更改变量被使用的所有位置）
