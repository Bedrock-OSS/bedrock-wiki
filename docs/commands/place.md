## Introduction

The `/place` structure was introduced in Preview 1.21.50.26 along with subcommands `structure` and `jigsaw`. Soon after `feature` and `featurerule` were introduced. As of 1.21.130 the command is fully stable.

## Syntax

- There are four different subcommands for `/place`.
    - `structure` places a jigsaw structure which can be trial chambers, trail ruins, or any custom jigsaw structures that may exist.
    - `jigsaw` places a specified jigsaw block's name field from a specified template pool.
    - `feature` places a feature at the specified position.
    - `featurerule` places a featurerule at the specified position.

## Arguments

- Phrases not contained in angle  <>  or square  []  brackets instruct you to type it as-is.
- Phrases contained within brackets are variables, these need to be replaced:
    - **` <> `** Angle brackets mean the variable is required.
    - **` [] `** Square brackets mean the variable is optional.

## Variables

- `structure` has mutliple variables. They are defined in the following order. The first field, `structure` is required.
    - **` structure `** is the identifer of a structure to place. `minecraft:trial_chambers`, `minecraft:trail_ruins`, and custom jigsaw structures, if any, are valid.
    - **` pos `** is the coordinates to begin generation of the structure. This is where the start piece will be placed. If not set it will place at the executors position.
    - **` ignoreStartHeight `** can be set to `true` or `false` and if `true` it will tell the game to ignore the structures set `heightmap_projection` and `start_height` values and place the structure on the executors y level.
    - **` keepJigsaws `** can be set to `true` or `false` and if `true` all jigsaw blocks, if any, will ignore their turns into field and remain in the structure. This is for debugging purposes.
    - **` includeEntites `** can be set to `true` or `false` and if `true` (which is the default) entities saved within the structure template pieces generated by the structure will be spawned.
    - **` liquidSettings `** can be set to `apply_waterlogging` or `ignore_waterlogging`. `apply_waterlogging` is the default and will waterlog and waterlogable blocks that are placed where water previously existed.
- `jigsaw` has multiple variables. They are defined in the following order. The first three fields up to but not including `pos` are required.
  - **` pool `** is the identifer of the template pool to search through.
  - **` jigsawTarget `** is the name field of a jigsaw block in a structure template in the previously specified `pool` variable. If no element of the specfied pool has a jigsaw block with that name field the command will fail.
  - **` maxDepth `** a number from 1-20 inclusive that tells the command how many times the jigsaw blocks in the generated structure template should spawn pieces. It works the same as the `max_depth` field in jigsaw defintion files.
  - **` pos `** is the coordinates to begin generation of the structure. This is where the start piece will be placed. If not set it will place at the executors position.
  - **` ignoreStartHeight `** can be set to `true` or `false` and if `true` it will tell the game to ignore the structures set `heightmap_projection` and `start_height` values and place the structure on the executors y level.
  - **` keepJigsaws `** can be set to `true` or `false` and if `true` all jigsaw blocks, if any, will ignore their turns into field and remain in the structure. This is for debugging purposes.
  - **` includeEntites `** can be set to `true` or `false` and if `true` (which is the default) entities saved within the structure template pieces generated by the structure will be spawned.
  - **` liquidSettings `** can be set to `apply_waterlogging` or `ignore_waterlogging`. `apply_waterlogging` is the default and will waterlog and waterlogable blocks that are placed where water previously existed.
- `feature` has 2 variables. `feature` is required. A feature will fail to place if the postion that is specified is not normally a place it could spawn. For example a ore feature that can only replace stone cannot be placed in air.
  - **` feature `** is the identifer of a feature to place.
  - **` pos `** is the coordinates to begin generation of the structure. This is where the start piece will be placed. If not set it will place at the executors position.
- `featurerule` has 2 variables. `featurerule` is required. A featurerule will fail to place if the postion that is specified is not normally a place that the feature rule's feature to place could spawn. For example a feature rule placing a ore feature that can only replace stone cannot be placed in air.
  - **` featurerule `** is the identifer of a feature rule to place.
  - **` pos `** is the coordinates to begin generation of the structure. This is where the start piece will be placed. If not set it will place at the executors position.

## Examples

<CodeHeader></CodeHeader>

```yaml
# Places a trial chamber with all of it's jigsaws at the players position and y level
/place structure minecraft:trial_chambers ~ ~ ~ true true true ignore_waterlogging

# Places a trail ruins building with it's jigsaws at the players position.
/place jigsaw "minecraft:trail_ruins/buildings" minecraft:building_anchor 10 ~~~ true true

# Places a diamond ore feature if player is inside stone or deepslate
/place feature minecraft:diamond_ore_feature ~~~

# Places a diamond ore featurerule if player is inside stone or deepslate
/place featurerule minecraft:overworld_underground_diamond_ore_feature ~~~
```
